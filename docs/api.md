# API reference

Base URL in development: `http://127.0.0.1:8000`
Interactive docs (generated by FastAPI): `http://127.0.0.1:8000/docs`

All durations are in **simulator ticks**. One tick is one simulation step; by
default a passenger advances one row per tick, stowing a bag costs 6 ticks and
sitting without a bag costs 2.

Errors use a single envelope:

```json
{ "error": { "code": "policy_not_found", "message": "No saved policy named 'x'.", "detail": null } }
```

| Code | Status | Meaning |
|---|---|---|
| `invalid_request` | 422 | A config field failed validation. `detail` lists `{field, problem}`. |
| `policy_required` | 400 | `strategy: "rl"` was sent without a `policy`. |
| `policy_not_found` | 404 | No saved policy with that name. |
| `job_not_found` | 404 | Unknown training job id (jobs live in memory). |
| `network_error` | — | Client-side only: the frontend could not reach the API. |

## `POST /api/simulate`

Runs one boarding and returns the **full recorded trajectory**.

Request — see [`config.example.json`](../config.example.json):

```json
{
  "config": { "aircraft": "a320", "n_passengers": 150, "gate": "front",
              "arrival": "random", "luggage_fraction": 0.6, "seed": 42 },
  "strategy": "wilma",
  "policy": null
}
```

Response:

| Field | Shape | Notes |
|---|---|---|
| `decks` | `[{name, rows, cols, aisleCols, blocks, doors}]` | Cabin geometry. `cols` includes aisle columns; `aisleCols` lists their indices. |
| `passengers` | `[{d, r, c, ac, t, bag, id}]` | Index in this array is the passenger id used in `frames`. `d/r/c` = deck/row/column of the assigned seat, `ac` = the aisle column that seat is reached from, `t` = window\|middle\|aisle, `id` = e.g. `"12C"`. |
| `frames` | `Delta[][]` | One entry per tick. Each `Delta` is `[passengerIndex, state, posRow]`. |
| `congestion` | `number[][]` | One entry per tick: `[walking, stowing, blocked, seated]`. |
| `stats` | `{ticks, blocking_events, blocked_ticks, avg_wait, n_passengers, seed}` | |

### Frames are delta-encoded

`frames[t]` contains **only the passengers whose `(state, posRow)` changed at
tick `t`**. A client must accumulate:

```ts
let current = Array(n).fill({ state: QUEUED, posRow: -1 });
for (const frame of frames) {
  current = current.slice();
  for (const [pid, state, posRow] of frame) current[pid] = { state, posRow };
  // `current` is now the complete cabin state at this tick
}
```

This is what `frontend/src/lib/trajectory.ts` does, and why playback speed and
scrubbing never re-run the simulation. `posRow` is the passenger's row position
in the aisle while moving, and the seat row once seated; it is `-1` before they
board.

`stats.ticks` equals `frames.length - 1` — the trajectory records the initial
state at tick 0.

## `POST /api/compare`

Runs every selected strategy over the **same seed sequence**, so the manifest,
seat assignment and bag draw are identical across strategies.

```json
{ "config": { "aircraft": "mid", "seed": 1 },
  "strategies": ["random", "wilma", "steffen", "rl"],
  "trials": 10,
  "policy": "rl_agent_mid" }
```

Seeds used are `config.seed … config.seed + trials - 1`. Rows come back sorted
by `mean_ticks` ascending and include `std_ticks`, `min_ticks`, `max_ticks`,
`mean_blocked_ticks`, `mean_avg_wait` and the raw `per_seed` array.

`trials` is capped at 40 and `strategies` at 6 to keep the request bounded; a
200-seat cabin × 6 strategies × 40 trials is a few seconds of CPU.

## `POST /api/train` → `202 Accepted`

Starts a tabular policy-gradient run **in a background thread** and returns
immediately with a job handle. The request never blocks on training.

```json
{ "config": { "aircraft": "mid", "seed": 1 },
  "episodes": 2000, "restarts": 2,
  "alpha": 0.25, "batch": 16,
  "save_as": "my_policy" }
```

There is no `gamma` field. The reward is −1 per tick and the objective is total
boarding time, so the trainer is undiscounted by construction (γ = 1) and the
request rejects `gamma` with 422 rather than accepting a value it would ignore.

`save_as` must match `^[A-Za-z0-9_\-]{1,40}$` (so it cannot escape the policy
directory) and may be `null` to train without persisting.

Returns a `TrainJob` with `status: "queued"`.

## `GET /api/train/{job_id}`

Poll for progress. While running:

```json
{ "job_id": "2b6a00246386", "status": "running",
  "episodes_done": 640, "episodes_total": 4000,
  "curve": [[64, 171.3], [128, 166.8]], "result": null, "message": null }
```

`curve` is `[episode, mean ticks]` for the **greedy** policy on a held-out
validation seed set — not the sampled training episodes, which are much slower
than the policy being learned.

On completion `status` becomes `"done"` and `result` contains:

| Field | Meaning |
|---|---|
| `saved_as` | Policy name, or `null` if not persisted. |
| `validation_ticks` | Best restart's mean on the validation seeds (how the restart was chosen). |
| `eval_mean_ticks` | The saved policy re-run on those seeds. |
| `baseline_ticks` | `random` / `wilma` / `steffen` on the same seeds, for an honest comparison. |
| `states` | Number of distinct tabular states visited. |
| `per_restart` | Per-restart validation scores. |
| `greedy_curve` | The full evaluation curve. |

On failure `status` is `"error"` and `message` carries the exception.

**Limitation:** jobs are held in an in-process dict (last 32) and are lost when
the API restarts. Saved policies survive, because they are written to
`artifacts/policies/`.

## `GET /api/policies`

```json
[{ "name": "rl_agent_mid", "kind": "agent",
   "label": "Trained agent — specialist (best overall)",
   "note": "Policy gradient, 10000 episodes, best of 5 restarts · 157.1 ticks on the mid cabin",
   "meta": { "algo": "...", "eval_mid_mean": 157.1 } }]
```

Sorted strongest first. `kind` separates three very different things that would
otherwise look identical in a dropdown:

| `kind` | What it is |
|---|---|
| `agent` | Trained for use. `rl_parity_mid` (best), `rl_agent_mid`, `rl_agent`. The UI auto-selects the strongest. |
| `user` | Trained in the app via `/api/train`. |
| `reference` | Algorithm-comparison artifacts (`rl_mc`, `rl_sarsa`, `rl_qlearning`, `rl_linear`) kept to demonstrate *which algorithms fail on this problem*. They are slower than the heuristics by design, so `/api/policies` and `/api/options` **omit them**. `load_policy` still accepts them by name for scripted runs. |

Policies are plain JSON Q-tables under `artifacts/policies/`. The tabular state
is size-independent, so a policy trained on the 60-seat `mid` cabin can be
replayed on any aircraft preset.
